# 自动化与代理边界

## 代理说明

| 项目 | 当前实现 |
| --- | --- |
| 触发 | 用户显式调用 `$shaoxingshiye`，或宿主根据 Skill 描述匹配相关请求 |
| 所有者 | 用户控制当前任务；仓库维护者维护公开指令 |
| 自动运行 | 只在宿主任务内响应，不存在后台或定时运行 |
| 可读输入 | 当前对话、按需 Markdown、已同意的精简记忆，以及用户主动粘贴的办公 IM 内容 |
| 必需工具 | 无；本地记忆可选，失败时降级到当前任务 |
| 外部副作用 | 现实消息无；首次同意后可更新本地记忆，无任何平台写入能力 |
| 审批 | 现实发送、签字、联系或求助动作均由用户自行决定 |

## 提示词引导与硬边界

`SKILL.md` 包含首次建档、情绪支持、知识路由、建议格式和安全边界。这些属于模型引导，并非程序级强制控制。

真正的硬边界来自宿主环境：模型安全政策、文件系统权限、网络权限、工具参数校验和用户批准，以及 `memory_store.py` 的脚本级门禁（来源校验、条数上限、撤销机制）。仓库不能声称仅靠提示词彻底阻止越权或有害输出。

## 输出契约

常规回答应尽量包含：

1. 对用户情绪和核心矛盾的准确回应（情绪落地）。
2. 已知事实、合理推测和关键未知的区分。
3. 明确的首选建议及 2–4 个理由。
4. 必要时提供稳健/策略/强势版本、可发送话术和预期代价。
5. 一件下一步、观察窗口或停止条件。

用户只要回复话术时，第一屏先给一条可发送成品。若信息不足，代理只问 1–3 个会改变建议的问题；首次建档也不机械展开完整问卷。

## 失败处理

- 资料缺失：标注未知，不虚构。
- 资料矛盾：指出矛盾并请求纠正关键项。
- 高风险请求：拒绝危险操作部分，提供合法替代。
- 法律不确定：说明局限与时效，建议核对地区并咨询合格专业人员（12348/12351）。
- 工具不可用：继续提供纯文本支持，不假装已执行外部操作。
- 记忆写入失败：明确说明没有持久化，不显示"记忆更新"成功提示。
- 来源门禁拒绝（如把推断写入事件）：如实报告拒绝原因，不绕过。
