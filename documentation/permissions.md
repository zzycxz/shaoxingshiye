# 权限边界

## 运行角色

| 角色 | 能力 | 不能做什么 |
| --- | --- | --- |
| 用户 | 提供信息、选择是否采用建议、决定是否启用本地记忆 | 不通过本 Skill 自动获得同事或领导的私人数据 |
| 代理（FreeCodeZ/Codex 等） | 读取 Skill 与按需参考；用户同意后调用本地记忆脚本 | 不替用户发送消息、不读取聊天软件数据库、不绕过工具批准 |
| 仓库维护者 | 修改公开文件、审查贡献和发布版本 | 无权访问使用者在私人任务中的内容 |
| 贡献者 | 通过 Issue 或 PR 提交公开内容 | 不应提交可识别的真实职场案例、真实单位与同事信息 |

## 资源与操作矩阵

| 资源 | 用户 | 代理 | 维护者／贡献者 |
| --- | --- | --- | --- |
| `SKILL.md` 与参考资料 | 可读取 | 可读取 | 通过 Git 修改公开副本 |
| 当前任务对话 | 可提供和查看 | 仅按宿主上下文访问 | 默认不可访问 |
| 用户本地文件 | 按宿主授权 | 仅在宿主提供工具且用户授权时访问 | 不可访问 |
| 本地精简记忆 | 可同意、查看、暂停、撤销、失效标注和删除 | 仅按同意状态和脚本门禁读写 | 默认不可访问，绝不进入仓库 |
| 办公 IM 内容 | 用户自行粘贴或导入 | 仅分析用户提供的文本，不主动抓取 | 不可访问 |
| 外部消息或账号 | 用户自行操作 | 本 Skill 不要求写权限 | 不可访问 |
| GitHub 仓库 | 公开读取 | 无运行时要求 | 按 GitHub 仓库权限贡献 |

## 数据与权限实现

仓库本身没有用户数据库、令牌、角色声明或行级安全机制。`memory_store.py` 只在用户首次同意后于本地用户数据目录创建限量 SQLite 文件（`0600` 权限、目录 `0700`），并使用来源、条数和撤销校验；它不提供跨操作系统账号隔离。办公 IM 平台的企业侧会话存档、审批流等能力不属于本 Skill 的调用范围。
