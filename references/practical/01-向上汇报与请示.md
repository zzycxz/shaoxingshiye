# 01 向上汇报与请示

## 诊断先行：先判断卡在哪

| 卡点 | 信号 | 主策略 |
| --- | --- | --- |
| 领导不知道进展 | 出事后才被问"怎么不早说" | 定期结构化汇报 |
| 汇报没被记住 | 讲了很多，领导只问"所以结论呢" | 金字塔重构：结论先行 |
| 请示没有回音 | "知道了""再说" | 把问答题改成选择题 |
| 信息错配 | 领导嫌烦或嫌不够 | 校准颗粒度（阅读型给文档，倾听型给口头） |

## 结构：一页纸汇报骨架

```text
【结论】一句话：进展/风险/需要你决定什么
【关键数据】2–4 个数字或事实，不下判断
【选项与代价】A：…（收益/代价）；B：…（收益/代价）
【我的建议】选 A，因为……（对齐领导在意的目标）
【需要的支持】一句话：要人/要钱/要拍板，期限
```

依据：Minto 金字塔（流行框架但为行业通用语言）+ Gabarro & Kotter——汇报设计围绕**领导的目标与压力**，不是围绕"我做了什么"。

## 请示：选择题原则

- 问答题版（弱）："这个项目预算超了，怎么办？"
- 选择题版（强）："预算超 10%，两个方案：A 砍范围保时间（客户感知风险小）；B 加预算保范围（需你审批 8 万）。我建议 A，理由两点。今天定的话不影响里程碑。"

规则：选项 ≤ 3 个；每个带代价；给出明确建议；写明**决策期限**；给退出台阶（"如已有其他考虑，我按你定的来"）。

## 微信/IM 汇报三格式

- **进展同步**（1–3 行）："X 项目：今日完成 A，明日做 B，风险一个（C，已有应对）。不需要你操作，知会即可。"
- **请示**（见上，选择题）
- **坏消息**（先事实后方案，不垫长铺垫）："出现 X 问题，影响是 Y。我已做 Z 应对，需要你决定 W。"

坏消息规则：**第一时间报事实，同时带方案**——"报忧要缓"的老惯例只保留"先想好再开口"的部分，重大风险拖延不报是把用户的信任与法律责任一起押上去。

## 产出真空期（刚接手/尚无可交付时被问进展）

不解释原因、不提前任、不长铺垫。把"盘点"重构为真实进展：遗留梳理、依赖澄清、卡点清单都算；给**节点**而不是成果："周四前发您新版排期和第一个可交付件（先出 MVP 方案）。"确无任何可展示项时当场缩小颗粒止损："今天下班前我先把 X 部分发您。"接手初期领导主动问 = 还在关注名单上，回得好是加分项。

## 周期性文书：周报、述职与年终总结

- **周报** = 进展 + 风险 + 下周计划，不是流水账：用价值语言（13："重构后耗时降 40%"而非"做了重构"）；风险带应对；预告下周需要别人配合的事——提前要资源比事后催办好用（03 同源）。
- **述职/年终总结**：讲"超出本级职责的影响"而非苦劳清单（10 晋升答辩同源）——量化结果 + 我的角色 + 可证明人；素材来自平时维护的私人清单（13 弹药库）。
- **节奏**：周报固定时间发（建立确定性）；年终按季度回看弹药库补素材，别等年底挤。

## 颗粒度校准（家长式领导维度应用）

- 威权型：给结论与服从点，细节备查；不当场反驳（异议走 02）。
- 仁慈型：可适度分享困难与成长诉求，接受关心。
- 德行/制度型：对齐原则与标准，"按我们定的流程，这一步应该……"。

当众汇报/会议场景以 11 号文件为主（锚点与控场），本文件的骨架用于准备书面材料。

## 后续分支

- **积极**（批复/采纳）：确认理解复述一遍 + 明确执行节点。
- **含糊**（"再看看"）：48 小时后轻推一次（补充一个新信息而非催促）；再含糊则升级选项或转入 02 表达分歧。
- **拒绝**：问清顾虑（"你主要担心哪一点？我补数据"）；仍拒则记录在案（邮件确认），执行决定。

## 停止条件与红线

- 汇报不等于表功轰炸：同一事项不超过"事实+决策请求"两个动作。
- 不替领导写"他想听的话"而隐藏真实数据；数据可以选呈现角度，不可以造假。
- 涉及违法数据/文件的汇报要求 → 转知识 05 自保路径。
