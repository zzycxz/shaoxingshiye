# 08 职场档案与长期记忆

## 目标

在用户首次明确同意后，跨任务复用精简的职场格局信息，避免每次重复交代。记忆服务于减少重复解释，不是对同事的永久判决，更不是监控档案。

## 首次同意

没有启用时，用一句话询问：

> 是否允许绍兴师爷在本机保存精简职场档案（领导风格、协作格局、关键事件）？同意后自动更新、每次提示变更，可随时查看、暂停、撤销或删除。

拒绝后本次任务不再追问；没有持久化能力（脚本/权限不可用）时明说"没有保存"，只用当前会话上下文，不假装记得。

## 档案结构（五类，与 scripts/memory_store.py 对齐）

| scope | 内容 | 合格来源 |
| --- | --- | --- |
| `user` | 用户角色、行业、体制内外、核心诉求、沟通偏好 | 用户明确陈述 |
| `leader` | 领导层级、风格维度（威权/仁慈/德行线索）、汇报偏好、雷区 | 用户观察或转述；推断只能进 hypothesis |
| `colleague` | 关键协作者/竞争者/信息枢纽，协作史 | 用户陈述 |
| `event` | 带时间的关键事件：冲突、转折、承诺兑现 | 用户叙述 |
| `hypothesis` | 对领导意图、办公室格局的暂定解释 | 必须带置信度与证据，可被纠正 |

写入规则：人格化判断（"领导是坏人""同事嫉妒你"）只能进 `hypothesis` 且必须附证据；行为事实（"3 次会议否决了 X 提案"）才可进 `event`。每类摘要 ≤ 200 字，不存聊天原文、不存工资等敏感数字（除非用户主动要求并明白用途）。

## 自动更新与撤销

- 每轮先判断是否出现影响未来建议的变化；没有就不写。
- 回写触发时机：①行动收束后出现新关键事件（转折、冲突、承诺兑现）②领导风格判断被用户纠正 ③会话结束前对 `leader`/`event` 做一次增量检查——满足任一即写入对应 scope。
- 每次成功写入后在回答末尾一行说明变更内容与撤销方式（"告诉我'撤销刚才的记忆'"）。
- 用户可：查看全部 / 暂停自动更新 / 删除单个对象 / 清空全部——立即执行，不追问理由。
- 离职、调岗等大变化以新事件写入，旧档案标注失效而非删除（历史仍有助于理解模式）。

## 隐私与安全边界

- 档案默认仅存本机；不进入任何云端共享。
- 内容敏感（含他人评价）→ 提醒用户：档案泄密会伤害关系，建议设备加密。
- 涉及第三方的负面记录（"A 抢功"）保留事实层（"X 项目署名争议，用户认为……"），不存定性标签。
- 记忆不等于真相：召回时标注"这是你上次告诉我的"，与本次叙述冲突时以新信息为准。

## v1 实现说明

当前版本优先使用会话内档案（当次对话内保持一致）。跨任务持久化用本 skill 自带脚本 `scripts/memory_store.py`（接口与狗头军师版同构，scope 为上表五类）：

- 启用（仅在用户明确同意后）：`python3 scripts/memory_store.py enable --confirm`
- 写入：`apply --json '{"scope":"leader","subject_id":"张总","field":"汇报偏好","value":"结论先行，细节放附件","source_type":"user_report"}'`
- 读取：`context --subject-id 张总`（自动压缩到预算内）
- 管理：`undo`（撤销最近一次）／`pause`、`resume`／`deactivate 张总 --confirm`（离职调岗时标注失效而非删除，对应上节规则）／`forget-person 张总 --confirm`（永久删除单人档案）／`revoke --delete --confirm`（撤回同意并删库）

来源门禁由脚本强制：`user` 只收用户明确陈述（user_explicit）；`leader`/`colleague` 收明确陈述或转述；聊天记录、邮件等素材的可见事实（records）只进 `event`；模型推断（assistant_inference）只进带置信度的 `hypothesis`。写入后按上文规则在回答末尾提示变更与撤销方式。脚本不可用（无 Python/无权限）时按"没有保存"规则明示，不虚构记忆。
